---
name: consensus
description: Maintain a shared understanding of goals, assumptions and explicit agreements during a conversation. Use when discussing direction, revising goals, or confirming decisions.
allowed-tools: Bash
---
Favor a natural collaborative conversation, not a checklist. Share one idea at a time and ask no more than one essential question unless requested. If the user clearly confirms a decision, save it as `agreed`; if the AI proposes an interpretation not yet confirmed, save as `assumed` only when useful. Open questions may be stored as `open`. Run the state manager exactly as the Consensus Harness context shows it (it pins the project, and in the home folder the session); fall back to `node "${CLAUDE_PLUGIN_ROOT}/scripts/state.mjs"` only if that context is missing. Use `goal -` for an agreed goal; `add <agreed|assumed|open> -` for a new item; `edit <id> <status> -` or `remove <id>` with the short id shown in the injected list (or a full id from `status-json`). `-` reads the text from stdin: always pass it through a quoted heredoc (`<<'EOF'` … `EOF`), never inside double quotes, so `$(...)`, backticks and `$VAR` in the user's words are stored as written and not run by the shell. Do not claim a consensus was saved unless the command succeeded. Keep state concise and avoid recording secrets or sensitive personal data. Never treat silence as agreement. A general yes to a multi-part answer agrees only to the main recommendation: record that as `agreed` and any details the user did not name as `assumed`. Write agreed items and the goal in the user's own words, without adding detail they did not state. If the harness is off, do not update the state.

When the unslop skill is in use, its confirmed "Direction" is a consensus decision: record it as a single agreed item starting `UI direction:` (product, character, world, moments, signature, condensed), and reuse an existing `UI direction:` item in later unslop runs instead of deriving a new direction. Never record the direction before the user has answered unslop's direction question. Save the audit's heavy/light/no-slop verdict as `assumed`. If the direction changes later, edit the existing `UI direction:` item instead of adding a second one.
